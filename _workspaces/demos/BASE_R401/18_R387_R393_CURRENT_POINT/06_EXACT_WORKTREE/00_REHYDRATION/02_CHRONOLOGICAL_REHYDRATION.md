# Chronological rehydration: how V2 arrived here

This chronology exists because a short manifesto did not reliably reproduce the method. The receiving
agent should understand the sequence of problems, corrections, and working artifacts.

## 1. Distributed-science reconstruction

The project began from the claim that useful mechanisms are scattered across cultures, schools,
disciplines, geography, politics, technology constraints, war, historical timing, and the politics of
science. The aim was to reconstruct mechanisms with independent judgment rather than use consensus as
an automatic truth filter. A canonical 4,000-record inventory and chronological rehydration archive
preserved this starting space.

## 2. Primitive-family saturation

The 4,000 records were compressed into a provisional ontology. A global saturation pass extended the
base frontier from IM-312 to IM-384. The stopping criterion became mechanism saturation, not an arbitrary
target count: named concepts or shell refinements were not promoted into new primitive families unless
they changed a proof, estimator, decision rule, representation, operator, or system behavior.

## 3. Composition rather than endless family hunting

The work shifted from finding IM-385 to combining families. Compatibility prefilters, provenance
registries and ranked directed compositions were created. Prior-art collision was treated as market/IP
information, not as proof that a mechanism could not work. The key question changed from “will academia
accept it?” to “can it produce a real result or product?”

## 4. Parent products and Foundry

Sixty-nine executable parent products became the first product substrate. Foundry explored their
interactions and produced P001–P145. Some historical sources were lost, so evidence tiers were made
explicit: original executable material, salvaged source with rebuilt tests, mechanism reconstruction
from results, spec-executable reconstruction, and new replacement for an unrecoverable ID. The complete
Foundry state passes 214 test files / 806 tests / 0 failures, but that regression proves code contracts,
not universal field validity.

## 5. Correction of destructive product logic

Early work sometimes treated strong comparators, prior art, or a failed real-life shell as reasons to
“kill” ideas. The user corrected this. The method now localizes failure and uses it to find boundaries,
routers, repairs and better application domains. Product generation is directed toward working things,
not toward maximizing rejection severity.

## 6. LCB rescue and Core V2

A separate LCB/r50 product-development stream contributed 96 executable/addressable kernels and a
strength/weakness “core” idea. V2 revised that idea: strengths and weaknesses form a typed puzzle graph,
but tag overlap is only a candidate generator. A real composition needs compatible inputs/outputs and a
non-additive mechanism. Standalone value and component value are evaluated separately.

## 7. Foundry-inclusive V2 universe

V2 integrated 96 LCB kernels, 69 Foundry parents and 145 Foundry products into a 310-record registry.
The typed pass generated 15,704 directed candidates and retained a ranked 1,000-row work queue. Twelve
routes received explicit mechanism adjudication. Scores prioritize investigation; they never erase
lower-ranked products.

## 8. Completed V2 composites

V2P001 SAVA combines shared-capacity allocation with expected verification liquidity. It removed
83/180 (46.11%) of naive shared-pool double counting in its deterministic benchmark and retains exact
small-portfolio and scalable polymatroid routes.

V2P002 MFQA combines decision-value gating with multi-fidelity budget allocation. A near-boundary,
high-correlation case reduced its program variance proxy by 53.36% relative to fine-only; low
correlation routed to fine-only, while a far-boundary case bought nothing and preserved the budget.
Decision value and variance proxy remain separate outputs.

## 9. Current frontier

The main lab had begun inspecting MultiFidelityBudgetControllerV0 → P144 DPAI when this independent-lab
handoff was requested. That route is a candidate, not an obligation. Other curated routes include
ObservationPolicyConfoundingGuardV0 → P138 SPIA, SafeProblemReducerV0 → P143 DLIC, and
EffectiveDiversityGuardV0 → P003 SANP. The independent lab may discover stronger cross-product routes
by reading the actual code.
