# Methodology and Visibility Delta — R394 to R398

## 1. Product mining changed from edge chasing to cluster adjudication
R393 left 15,578 fresh pairs grouped into 649 mechanism clusters. From R394 onward, raw/native score was used only for work ordering. Batches of diverse cluster representatives were opened, then rejected early if the supplier could not legally modify the consumer's state/objective/feasible set or if the proposal collapsed into an existing deep product family.

## 2. Semantic bridges are authority, not convenience
Several superficially attractive compositions were rejected because they required invented semantics: covariance could not be reinterpreted as directed information flow, randomization p-values could not become posterior culprit probabilities, Gaussian state means could not be softmaxed into DSBC simplex beliefs merely to connect two modules, and hedge exposures could not be relabeled as information flow. A composition must use a bridge already supplied by parent code or explicitly declared by the caller with fail-closed validation.

## 3. Removal control became a structural obligation
A product is not accepted because both parents appear in the code. The mechanism-removal comparator keeps the consumer shell, data, optimizer, seed, costs and constraints fixed while deleting only the proposed coupling. Collapse regions must reproduce the control exactly when the new mechanism has no authority/effect.

## 4. Working region is not universal superiority
R394–R398 deliberately preserved losing sensitivity cells. V2P054 loses when consequence ranking is wrong; V2P055 collapses when measurement is free/nearly perfect; V2P056 can change topology, collapse, or fail closed depending on uncertainty/tolerance; V2P057 can hurt actual observability when declared risk is miscalibrated; V2P058 can materially worsen RMSE under wrong support. These failure regions are part of the product contract.

## 5. Exact-signature telemetry rule
Early work exposed stale telemetry risk. A pilot generated before a code/test hardening change is superseded. Mechanics telemetry must bind the final current source/test shell. It calibrates executable placement only; it is not empirical learning.

## 6. Regression inheritance is provenance-preserving
Unchanged large surfaces may inherit a prior clean receipt only after byte-tree identity is proven. Any byte drift invalidates inheritance. New product surfaces and state-sensitive search/telemetry/authority/closure surfaces run fresh. This prevented long regressions from becoming ritual while retaining fail-closed evidence semantics.

## 7. Historical closure tests must be future-safe
Several older release tests incorrectly asserted that the physical future must contain exactly the historical suite count. These were corrected to audit historical authority without rejecting later candidate overlays. Historical numbers remain immutable; the test semantics become time-aware.

## 8. Product artifact visibility is part of correctness
V2P053 earlier demonstrated that working code without `PRODUCT_RESULT.md` could be invisible to suite discovery. Artifact completeness is therefore a product contract. Packaged regression was also changed earlier to auto-discover every `V2P*/test_*.py` rather than a fixed ID range.

## 9. Negative knowledge is pair-local and persistent
Rejected pairs are carried into the next frontier rebuild. A failed composition does not kill either component globally. The point is to avoid rediscovering the same invalid bridge/family collision while allowing each component to participate in other compositions.

## 10. Saturation evidence is meaningful
R398 required multiple waves before V2P058 appeared. Entire 8–12 candidate batches collapsed into existing families or failed interface authority. This is useful evidence that the pair-composition frontier is becoming harder, not a reason to invent products.
