# LabAllCompass project contract

This repository is a research-and-product laboratory. The main loop is practical: inspect existing products/results/code/tests and R/T/IM memory, search broadly when useful, build or combine a promising mechanism, run the cheapest discriminating code/test, keep what works, record what fails, and move to the next product/problem.

## Core boundaries

- R### research rounds, T## reusable mechanisms, IM-### primitives, products, tests and negative results remain useful Lab memory.
- A local failure does not globally kill a mechanism.
- Contracts and provenance may record useful facts, but they must not choose the research direction or become prerequisites for ordinary exploration, coding or testing.
- Do not treat document reading, gate completion, receipts, hashes or metadata as scientific progress by themselves.
- Coherence OS is memory/catalog/integrity through the active history. It may help find prior work, contradictions and failures, but it does not choose research direction or impose a stage order.
- Lab Runtime is optional persistence/execution journaling. Its routes are suggestions, not scientific gates.
- `POST_R178_SALVAGE_ARCHIVE/` preserves discarded R179-R192 code/mechanics only. Never auto-load, retrieve, rank, compose or cite it during normal Lab work; a salvaged mechanic may return only through a fresh experiment and a new identity.
- Active Turing history ends at R178. The next clean round is R179; R179-R192 from the discarded branch are not active Lab history.

## Working style

Start from an interesting problem, product weakness, historical clue, mechanism, or promising combination. Use Lab products and R/T/IM memory as tools, not gates. Search external material according to the problem. Prefer code, tests, benchmarks, counterexamples and measurable improvements. When a path is weak, record the failure and move on.
